# Путёвка — правила проекта

Сервис путевых листов для таксопарков (SaaS). Водитель получает лист в телефоне (PWA), диспетчер, медработник и контролёр ставят отметки или электронные подписи, платформа продаёт парками тарифы и услуги своих подписантов. Язык интерфейса, текстов и коммитов — русский.

## Стек и запуск
- Node.js 20+, Express 4, SQLite (better-sqlite3), серверный HTML без фреймворков. Зависимости: express, better-sqlite3, bcryptjs, qrcode. Новые зависимости — только если без них никак.
- `npm install` → `DB_PATH=data/demo.db npm run demo` → `DB_PATH=data/demo.db npm start` (порт 3000).
- `npm test` — сценарные тесты: `test/smoke.mjs` (платформа, листы, оплата), `test/yookassa.mjs` (ЮKassa на поддельном API), `test/epl.mjs` (ЭПЛ и услуги подписантов), `test/astral.mjs` (оператор ЭПД «Калуга Астрал» на поддельном API), `test/push.mjs` (push-уведомления), `test/launch.mjs` (оферта, политика, `/health`, резервные копии). Перед каждым коммитом все должны проходить.
- Сервер: `docker compose up -d` (приложение + Caddy с HTTPS + ежедневные копии `scripts/backup.mjs`), см. README «На сервер».
- Демо-входы: платформа `root` / `root-demo-pass`; парк `owner` / `owner-demo`, `disp` / `disp-demo`, `medic` / `medic-demo`; исполнители сервиса `smed` / `smed-demo`, `smech` / `smech-demo`; водители `+7 900 000-00-01…05`, пароль `1111`.

## Устройство
- `src/server.js` — сборка приложения, CSP, проверка источника POST, общий `ctx` для маршрутов.
- `src/db.js` — схема и миграции (`MIGRATIONS`: только добавление колонок), тарифы и цены услуг по умолчанию.
- `src/service.js` — правила листа: выписка (до 6 дней вперёд), медосмотр, выпуск, сдача, приём, отмена с возвратом, сроки документов. Бизнес-ошибки — `UserError`, их текст показывается пользователю.
- `src/billing.js` — баланс, тарифы, подписка (`paid_until`, продление только из баланса, без денег парк в режиме `suspended`).
- `src/payments.js` — ЮKassa (карта, СБП), тестовый режим без ключей, счета с QR по ГОСТ, выписка 1С. Деньги на баланс — только через `credit()` (идемпотентно).
- `src/epd.js` — ЭПЛ: титулы Т1–Т5, права на подпись, пакетное подписание, регистрация в ГИС ЭПД, интерфейс оператора ЭПД (`OPERATOR_METHODS`). Оператор выбирается `EPD_OPERATOR`: `sandbox` (по умолчанию) или `astral` (`src/epd/astral.js`; пути API не сверены с документацией — см. README). Подписание применяется только по ответу оператора и только с сертификатом самого подписанта.
- `src/push.js` — Web Push без зависимостей (VAPID, aes128gcm). События — через `notify()` внутри транзакции изменения (очередь `push_outbox`), плановые — `scheduled()` раз в минуту. Ключи `VAPID_*`, без них выключено.
- `src/routes/*` — маршруты по ролям: `public` (сайт, вход, регистрация, QR-проверка `/c/:token`, `/offer`, `/privacy`), `driver` (`/d`), `park` (`/p`), `super` (`/s`), `service` (`/x`, исполнители сервиса), `pay` (вебхук ЮKassa, уведомления оператора ЭПД `/epd/notify`, тестовая оплата).
- `src/views/*` — HTML-шаблоны (функции, возвращающие строки; всё пользовательское — через `esc()`).
- Android-приложение для RuStore — TWA через Bubblewrap: `scripts/twa-config.mjs` → `android/twa-manifest.json`, `/.well-known/assetlinks.json` из `TWA_SHA256`.
- `public/` — `app.css` (токены цветов, тёмная тема), `app.js` (небольшие улучшения, страницы работают без JS), `sw.js` (офлайн для листов водителя), манифест и иконки.

## Правила, которые нельзя нарушать
1. **Изоляция парков.** Каждый запрос к данным парка фильтруется по `park_id`. Новый маршрут — новый тест «второй парк этого не видит».
2. **Каждый подписывает только своей подписью.** Никакого подписания за другого человека, никакого хранения или передачи чужих ключей (63-ФЗ, ст. 10). Сессию подписания подтверждает только её владелец. Медосмотр (Т2) — только медработник и только УКЭП. Выпуск и приём (Т3–Т5) — только аттестованный контролёр. Порядок титулов: Т1 → Т2 → Т3+Т4 → Т5.
3. **Никаких нарисованных штампов и подписей.** Бумажный лист печатается с пустыми местами под настоящие штампы. Электронный — с блоками электронных подписей.
4. **Отметки только в день смены и текущим временем.** Заранее проштамповать или подписать медосмотр и выпуск нельзя.
5. **Выписанный лист не меняется.** Реквизиты, водитель и машина «замораживаются» в `snapshot` при выписке.
6. **Деньги.** Все суммы — в копейках, целыми числами. Зачисление — только через `payments.credit()`, списание — через `billing.post()`. Уведомлению платёжки не верить: статус перепроверяется через API.
7. **Безопасность.** CSP без inline-скриптов и inline-стилей (никаких `style="..."` и `<script>` в HTML), формы — POST с проверкой источника, пароли — bcrypt, перебор ограничен.
8. **Персональные данные** (ФИО, телефоны, ВУ, СНИЛС) не выводить на публичных страницах: QR-проверка показывает только инициалы.

## Стиль
- Тексты интерфейса — короткие, по-русски, от лица пользователя: кнопка говорит, что произойдёт («Подписать выпуск»), ошибка — что не так и как исправить.
- Цвета только через токены в `:root` `app.css`, каждый новый экран — проверить на телефоне 390 px и в тёмной теме.
- Код без лишних абстракций: маленькие функции, комментарии там, где правило бизнеса неочевидно.
